### 2.1 Track A — CPU decode (not cuDNN-sensitive)

| Backend | Target combo (seq16, stride4) warm | Baseline (seq4, stride1) warm |
|---|---:|---:|
| `cv2_seq` | 0.938 clips/sec | 3.471 clips/sec |
| `cv2_nothreads` | 0.936 clips/sec | 3.542 clips/sec |
| `decord_cpu` | 4.170 clips/sec | 8.473 clips/sec |
| `pyav` | 7.39 clips/sec *(from REPORT.md; `av` not in `/opt/ml`, not re-run)* | — |

- **DataLoader worker sweep (A3):** plateaus at 12 workers (2.16 clips/sec), flat through 20 (2.19). **Cap at 12.**
- **A6 multiprocessing extraction:** 2.01 videos/sec → projected **1.66 h** for the full corpus.

### 2.2 Track B — NVDEC / GPU decode

- `ffmpeg_cuda_cli`: 1.29 clips/sec target — **still far slower than CPU pyav.**
- `decord_gpu`: non-functional (`DECORDError: CUDA not enabled` — installed wheel limitation).
- `torchcodec_cuda` + B5 session sweep: **NOT re-run** (`torchcodec` not in `/opt/ml`; the "973–1026 clips/sec" raw numbers are the speed of failing instantly — **do not cite**).
- **Verdict: no GPU/NVDEC decode path is worth using here.**

### 2.3 Track C — Intel iGPU

VA-API (`-542398533`, no `/dev/dri`), QSV (same), `torch.xpu` (`is_available()=False` even on prod torch), IPEX, OpenVINO — **all failed. No viable Intel-GPU path exists in this WSL2 environment.**

### 2.4 Track D — face detection

| Detector | Throughput | Full-corpus projection | Notes |
|---|---:|---:|---|
| **YuNet (CPU)** | **102.99 fps** | ~1.56 h | ships inside opencv; avg 1.00 faces/frame |
| MTCNN-CUDA | 20.53 fps *(cuDNN-OFF only)* | ~7.81 h | `facenet-pytorch` not in `/opt/ml`; cuDNN-ON number never measured |

**Verdict: use YuNet** — faster *and* zero extra dependency (opencv is already a hard dep).

### 2.5 Track E — training throughput (the core rerun)

| Config | clips/sec | Peak VRAM | vs cuDNN-OFF |
|---|---:|---:|---|
| fp32, default layout | 3.249 | 14,633 MB | ~flat |
| fp32, channels_last | **0.667** | 14,634 MB | **−85%, regression** |
| AMP fp16 | **13.899** | 8,479 MB | **+57%** |
| AMP bf16 | **13.426** | 8,479 MB | **+56%** |
| AMP bf16 + channels_last | **13.460** | 8,478 MB | **+53%** |

- **fp16 vs bf16:** 13.899 vs 13.426 (3.5% gap, noise). **Use bf16** — loss-scaling-free, NaN-safe on dark/compressed frames.
- **`torch.compile`:** compile 98.9s→54.3s, steady-state 0.308→1.297 clips/sec — still **10.7× slower than AMP.** Do not enable. ("Not enough SMs to use max_autotune_gemm" warning persists.)
- **`channels_last` regression:** real & reproducible; cuDNN's default heuristic mis-selects NHWC without `cudnn.benchmark=True` (proposed follow-up, not applied).

**Batch-size ceiling (AMP bf16 sweep):**

| Batch | clips/sec | Peak VRAM | State |
|---|---:|---:|---|
| 4 | **11.52** | 8.5 GB | clean, GPU-bound ✅ |
| 8 | 1.92 | 16.37 GB | usable, ~6× slower (card at full capacity) |
| 12 | 0.56 | 24.3 GB | **silent WDDM spill to system RAM** ❌ |
| 16 | 0.41 | 32.1 GB | worse spill ❌ |

**Batch=4 is the sweet spot. Batch=8 only if specifically needed. Never ≥12** — the system doesn't OOM cleanly, it silently degrades.

### 2.6 Ranked recommendations (each cites a measurement)

1. **AMP bf16 for training** — +56% throughput, −42% VRAM, loss-scaling-free (§2.5).
2. **Batch=4 under AMP** standard; batch=8 at ~6× cost; **never ≥12** (§2.5).
3. **Do not enable `torch.compile`** — 10.7× slower than AMP (§2.5).
4. **Do not enable `channels_last`** as configured — regression; revisit with `cudnn.benchmark=True` (§2.5).
5. **CPU `pyav` decode; no GPU/NVDEC** (§2.1–2.2).
6. **YuNet, not MTCNN**, for face crops (§2.4).
7. **Investigate `cudnn.benchmark=True`** — cheap follow-up, may fix #4 (not applied).
8. **Gradient checkpointing** — the way to escape the batch≥8 VRAM cliff if larger effective batches are needed (not measured).

## 3. Cache extraction & read throughput (celeb-df-v2, native-fps face-crop cache)

### 3.1 Extraction (one-time cost)

| | |
|---|---|
| Videos | 6,533 / 6,533 (100%, 0 failed) |
| Crops written | 2,470,703 (avg 378.2 / video) |
| Face-found rate | 99.77% |
| Cache size | 30.36 GB (q90 JPEG, 256×256) |
| Detector | YuNet, resize-before-detect capped at 1,600 px long side |

### 3.2 Read throughput — full 2.47M-crop cache, no GPU

| Location | Filesystem | Cold crops/s | Warm crops/s |
|---|---|---:|---:|
| `F:` (T7 Shield, external) | 9p/drvfs | 820.4 | 2,527.9 |
| `D:` (internal) | 9p/drvfs | 1,383.4 | 2,980.2 |
| `~/dfcache` (WSL native) | ext4 | 19,319.3 | 48,021.5 |

ext4 is ~19× faster than F: warm — but see §3.3: it doesn't matter under GPU load. A
shard-index sidecar fix (`data/cache.py`) gave F: a 3.08× warm speedup by eliminating
repeated `tarfile.getmembers()` scans.

### 3.3 Read throughput under real GPU training load — the number that decides cache location

ConvNeXt-Base, AMP bf16, channels_last, batch=4, `num_workers=12`, reading from **F:** (worst-case disk).

| seq_len | clips/sec | dataloader wait | wait % of step | GPU util | peak VRAM |
|---|---:|---:|---:|---:|---:|
| 8 | 25.92 | 0.25 ms | 0.16% | 76.1% | 5.08 GB |
| 16 | 13.56 | 0.27 ms | 0.09% | 86.1% | 9.04 GB |
| 32 (batch4) | 0.81 | 0.22 ms | 0.004% | 98.1%¹ | 17.26 GB² |
| **32 (batch2)** | **6.71** | 0.26 ms | 0.09% | 86.2% | **9.04 GB ✅** |

¹ "98.1% util" at seq32/batch4 is memory-pressure thrashing, not healthy saturation.
² **17.26 GB exceeds the card's 16.3 GB** — silent WDDM spill (same failure mode as batch≥12).
Throughput collapsed 16.7× (13.56→0.81). Confirmed *not* a worker-count issue: reran with
`num_workers=1`, peak VRAM identical to the decimal (17258.18 MB) — workers are CPU-only.

**seq_len=32 is usable only at batch=2** (same 64 images/step as batch4/seq16, VRAM matches to the decimal).

### 3.4 Epoch wall-clock projection (celeb-df-v2, 6,533 clips/epoch)

| Config | min/epoch |
|---|---:|
| seq8, batch4 | 4.2 |
| seq16, batch4 | 8.0 |
| seq32, batch2 | 16.2 |
| seq32, batch4 | 134.2 (not usable — VRAM overflow) |

### 3.5 Verdict

- **Cache location: F:** — GPU-bound at every usable config even on the slower drvfs disk; no ext4 staging copy needed.
- **seq_len: 16 at batch=4** (default) — best clips/sec-to-context tradeoff, VRAM well under ceiling.
- **seq_len=32 requires batch=2** — usable if more temporal context is needed later, at ~2× epoch time.
