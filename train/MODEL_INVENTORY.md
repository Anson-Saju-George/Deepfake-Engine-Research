# Model Inventory — Read-Only Pass

**Read-only.** Nothing under `train/` or `models/` was moved, deleted, or modified to produce this document. `models/` does not exist on disk (confirmed via directory listing) — nothing to inventory there.

**Method**: every directory under `train/` containing a `best.pth` or `last.pth` was treated as a run (23 found, cross-checked two independent ways — glob on `IMG-*`/`VID-*` dir names, and glob on checkpoint file presence — both returned the identical set of 23). Every metric below is read from that run's own files (`config.json`, `test_evaluation.json`, `final_summary.json`, `split_summary.json`). `docs/Results.md`/`docs/REVISION_AUDIT.md` were used **only** to build the comparison list in the next section, never as a metrics source. Where a value wasn't in that run's own files, the cell says `[UNKNOWN]` — nothing below is inferred or carried over from another run.

## Total count vs. the historical 22-run audit

**23 runs found on disk. 22 reconcile exactly against `docs/Results.md`'s table (5 image + 3 VID-SPA-02 loss variants + 1 VID-SPA-06 + 6 VID-ST + 2 VID-TMP-01 loss variants + 1 VID-TMP-02 + 2 VID-TMP-07 dataset-scope variants + 1 VID-TMP-08 + 1 VID-TMP-09 = 22).**

**The one extra**: `VID-TMP-04` (`Swin_Sequence`, `swin_base_patch4_window7_224`, `video_combined`, loss `none`) — present on disk, does **not** appear anywhere in `docs/Results.md`. Its own `history.csv` shows only 2 of a presumably-10-epoch run completed, `val_f1 = 0.0` both epochs (looks like a class-collapse failure, not a normal early stop), and it has no `final_summary.json`/`test_evaluation.json`/`test_predictions.csv` at all — it was very likely abandoned mid-run and never made it into the audit because it never produced a reportable result. See row flags below.

> **Caveat**: every metric in this document was produced under the **pre-rebuild protocol** (combined-corpus training, pre-decode-fix, legacy split engine, `stride=1` always — no run's `config.json` has a `stride` field at all, confirming stride wasn't a concept yet in this era). These numbers are retained for provenance only and are **not comparable** to post-rebuild results once T1–T3's work (identity-aware splits, stride-aware clips, face-crop cache) is used for a new training pass.

## Disk footprint

- **23 run directories, 30.12 GB combined** (`sum` of each run dir's own contents, includes `best.pth` + `last.pth` + any extra exported checkpoint + all summary/log files). `du -sh train/` reports 29G for the whole `train/` tree, consistent — checkpoints are essentially the entire footprint; code/`__pycache__` is noise by comparison.
- Every **image** run dir (5 of them) additionally contains a third checkpoint file named `final_<run_name>_valf1..._valacc....pth` that is the same size as `best.pth` (byte-identical size, not independently hashed this pass) — i.e. each image run is likely storing ~3 full copies of the same/near-same weights (`best.pth`, `last.pth`, `final_..._valf....pth`). Worth checking at cleanup time; not verified further here since that's a step-2 concern, not an inventory concern.
